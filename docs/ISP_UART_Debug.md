# SC1336 HDMI ISP 串口调试说明

本工程基于已经能正常输出 HDMI 的 `sc1336_hdmi` 工程复制而来。第一版 ISP 没有改 DDR/AXI 位宽，DDR 里仍然存 8-bit RAW/灰度数据；ISP 放在 DDR 读出之后、LCD/HDMI 输出之前。

```text
SC1336 DVP RAW8
    -> XYCrop
    -> DDR3 8-bit 帧缓存
    -> DDR 读出 RAW8
    -> VIP_RAW8_RGB888 Bayer 去马赛克
    -> 手动白平衡 AWB
    -> FrameBoundCrop 边界裁黑
    -> HDMI/LCD RGB888 输出
```

这样做的好处是：原来的灰度链路仍然保留，可以逐级打开 ISP 算法，哪里出问题就停在哪一级排查。

## 串口参数

串口波特率：`115200 bps`

发送单字符命令即可切换模式。FPGA 会回显收到的字符。

## 命令总表

| 命令 | 场景 | 作用 |
| --- | --- | --- |
| `L` | LCD/HDMI 本地测试图 | 不经过 DDR 和相机，验证显示时钟、HDMI 输出、RGB 管脚/线序 |
| `D` | DDR 动态灰度测试图 | 用 FPGA 内部图案写 DDR，再从 DDR 读出显示，验证 DDR 帧缓存闭环 |
| `X` | DDR 静态 XOR 灰度图 | 固定空间纹理，方便观察地址错位、行列错位、花屏 |
| `G` | DDR 固定灰度 `0xA5` | 验证 DDR 读写稳定性、显示亮度通路、是否有随机噪点 |
| `S` | 相机 RAW 灰度 | 相机 DVP 数据经过 DDR 后按灰度显示，验证 SC1336 输入链路 |
| `R` | 相机 RAW 灰度 | 与 `S` 相同，显式表示 RAW 模式 |
| `I` | Bayer 去马赛克 RGB | 在 RAW 灰度基础上打开 Bayer -> RGB，验证彩色重建 |
| `W` | RGB + 手动白平衡 | 在 `I` 基础上打开参考工程里的手动 AWB 增益 |
| `C` | RGB + AWB + 边界裁黑 | 在 `W` 基础上裁掉边缘无效像素，作为当前正常彩色显示模式 |
| `0` | Bayer 相位 0 | 设置 `mirror = 2'b00` |
| `1` | Bayer 相位 1 | 设置 `mirror = 2'b01` |
| `2` | Bayer 相位 2 | 设置 `mirror = 2'b10` |
| `3` | Bayer 相位 3 | 设置 `mirror = 2'b11` |

## 每个测试场景的意义

### `L`：LCD/HDMI 本地测试图

`L` 模式完全绕开相机和 DDR，只由 FPGA 内部测试图模块直接送到 HDMI/LCD 输出。

这个场景用于确认最底层显示链路是否正常，包括：

- `clk_video` / `lcd_dclk` 是否正常
- `lcd_hs`、`lcd_vs`、`lcd_de` 时序是否能被 RK3588 HDMI 输入识别
- `lcd_red/green/blue` 三个颜色通道是否有输出
- HDMI 线序、管脚约束、RK3588 显示脚本是否正常

正常现象：RK3588 能显示稳定测试图，颜色/灰阶随测试图变化。

如果 `L` 都不正常，后面不用继续测相机或 ISP，优先查 HDMI 时钟、LCD 时序、管脚约束、RK3588 采集脚本。

### `D`：DDR 动态灰度测试图

`D` 模式由 FPGA 内部生成动态灰度图，先写入 DDR3，再从 DDR3 读出来显示。

这个场景用于验证 DDR 帧缓存闭环：

- 写端 FIFO 是否正常
- AXI4 写 DDR 是否正常
- AXI4 读 DDR 是否正常
- 读写跨时钟是否稳定
- 帧地址递增和换帧逻辑是否正确

正常现象：画面稳定、有规律变化，不应该随机闪烁、撕裂、跳帧或大面积花屏。

如果 `L` 正常但 `D` 异常，问题大概率在 DDR/MIG/AXI4/FIFO 读写闭环，而不是 HDMI。

### `X`：DDR 静态 XOR 灰度图

`X` 模式同样走 DDR，但图案是静态的 `x ^ y` 灰度纹理。

这个场景比动态图更适合观察地址类问题：

- 行地址错位
- 列地址错位
- burst 边界错位
- FIFO 数据宽度拼接错误
- 帧起始地址不对

正常现象：应该看到稳定、规则的空间纹理。

如果图案斜线错乱、重复块异常、局部周期性断裂，通常说明 DDR 地址或数据打包有问题。

### `G`：DDR 固定灰度 `0xA5`

`G` 模式写入固定灰度值 `0xA5`，再从 DDR 读出显示。

这个场景用于把图案复杂度降到最低，观察纯数据稳定性：

- DDR 读写是否有随机 bit 翻转
- HDMI 输出是否有噪点
- 帧同步是否稳定
- 黑屏/白屏/灰屏亮度是否合理

正常现象：整屏应接近均匀灰色。

如果 `G` 出现随机彩点、条纹、闪烁，优先怀疑 DDR 读写稳定性、时序、供电或信号完整性。

### `S` / `R`：相机 RAW 灰度

`S` 和 `R` 都是相机 RAW 灰度模式。SC1336 的 DVP RAW8 数据经过 XYCrop、写入 DDR、再从 DDR 读出，然后直接 `{RAW, RAW, RAW}` 扩展成灰度显示。

这个场景用于验证相机输入链路：

- SC1336 I2C 配置是否完成
- `cmos_pclk` 是否存在
- `cmos_vsync` / `cmos_href` 是否正常
- DVP 8-bit 数据是否有效
- 相机 RAW 数据经过 DDR 后是否稳定

正常现象：应该看到黑白/灰度的相机画面。因为这是 Bayer RAW 直接当灰度显示，所以没有颜色是正常的，细节可能会有棋盘感或亮暗纹理。

如果 `D/X/G` 正常但 `S/R` 黑屏，优先查 SC1336 I2C 配置、DVP 管脚、PCLK、VSYNC、HREF。

如果 `S/R` 有画面但抖动、撕裂、滚动，优先查相机时序、帧同步极性、XYCrop 输入有效信号。

### `I`：Bayer 去马赛克 RGB

`I` 模式在 RAW 灰度基础上打开 `VIP_RAW8_RGB888`，把 SC1336 的 Bayer RAW8 转成 RGB888。

这个场景用于验证最基础的彩色重建：

- RAW8 数据是否符合 Bayer 排列
- Bayer 相位是否正确
- 3x3 行缓存是否工作
- RGB 输出链路是否正常

正常现象：应该出现彩色画面，但白平衡可能偏色，边缘可能有少量无效像素。

如果画面明显紫色、绿色、红蓝互换，通常是 Bayer 相位不对。此时发送 `0`、`1`、`2`、`3` 逐个切换 `mirror`，观察哪个颜色最自然。

### `W`：RGB + 手动白平衡

`W` 模式在 `I` 的基础上打开手动白平衡。当前使用 SC1336 参考工程里的固定增益：

```text
R = R * 409 / 256
G = G
B = B * 384 / 256
```

并且对 R/B 做饱和限制，超过 255 的值钳位到 `0xFF`。

这个场景用于验证：

- Bayer 去马赛克后的 RGB 数据是否可继续处理
- 白平衡增益是否方向正确
- 颜色是否比 `I` 模式更接近真实场景

正常现象：画面颜色应比 `I` 更自然，但不一定完全准确，因为这是固定手动白平衡，不是自动白平衡。

如果 `I` 的颜色相位就是错的，`W` 只会把错误颜色进一步放大，所以应先用 `0/1/2/3` 找到正确 Bayer 相位，再看 `W`。

### `C`：RGB + AWB + 边界裁黑

`C` 模式在 `W` 的基础上打开 `FrameBoundCrop`，将图像上下左右边界各裁掉 2 个像素并置黑。

这个场景用于正常显示和最终观察：

- 去掉 3x3 窗口/行缓存造成的边界无效像素
- 避免图像边缘出现彩边、毛刺或无效插值
- 作为当前第一版 ISP 的推荐彩色输出模式

正常现象：画面应是彩色、相对稳定，边缘极窄区域可能为黑色。

如果 `C` 正常，说明第一阶段 ISP 流程基本跑通。后续可以继续加 Gamma、对比度、锐化、降噪等算法。

## Bayer 相位测试：`0` / `1` / `2` / `3`

SC1336 输出的是 Bayer RAW8。Bayer 的起始颜色与传感器镜像、翻转、裁剪起点有关。如果相位不对，去马赛克后会出现明显偏色。

`0`、`1`、`2`、`3` 用于切换 `VIP_RAW8_RGB888` 的 `mirror[1:0]`：

```text
0 -> mirror = 2'b00
1 -> mirror = 2'b01
2 -> mirror = 2'b10
3 -> mirror = 2'b11
```

建议流程：

1. 先发送 `I`，打开 Bayer RGB。
2. 依次发送 `0`、`1`、`2`、`3`。
3. 观察哪个模式下颜色最自然，红蓝不互换，绿色不过量。
4. 确认相位后再发送 `W` 或 `C`。

SC1336 参考工程默认使用 `mirror = 2'b00`，所以本工程默认也是 `0`。

## 推荐上板测试顺序

```text
L -> D -> X -> G -> S/R -> I -> 0/1/2/3 -> W -> C
```

判断逻辑：

- `L` 正常：HDMI/LCD 输出链路基本正常。
- `D/X/G` 正常：DDR 写读闭环基本正常。
- `S/R` 正常：SC1336 DVP 输入链路基本正常。
- `I` 有彩色：Bayer 去马赛克基本工作。
- `0/1/2/3` 找到自然颜色：Bayer 相位确认。
- `W` 颜色更自然：手动白平衡方向基本正确。
- `C` 稳定显示：当前第一版 ISP 彩色链路可以作为后续算法测试基线。

## 当前版本注意事项

- 第一版没有把 RGB888 写入 DDR，而是 DDR 存 RAW8，显示前做 ISP。
- 这样资源和风险较低，适合先把颜色链路跑通。
- 当前 SC1336 初始化已限制曝光时间：`3e01 = 0x20`，`3e02 = 0x00`，
  即曝光约 `0x0200` 个半行时间。这样可以避免暗光下长曝光导致明显拖影/延迟。
  代价是暗场画面会更暗，后续应通过增益、Gamma、亮度映射或自动曝光策略补偿。
- 如果后续要做完整 RGB 帧缓存，建议用 32-bit 像素打包，不建议直接用 24-bit，因为当前 AXI 数据宽度是 256-bit，24-bit 像素无法整齐对齐。
- 当前 HDMI/LCD 的 `hs/vs/de` 仍由原 `lcd_driver` 输出，ISP 的数据链路参考 SC1336 示例工程。如果实际画面边缘有 1 到 2 像素偏移，后续可以把 ISP 输出的 `vs/hs/de` 也接入最终 HDMI 输出链路。
